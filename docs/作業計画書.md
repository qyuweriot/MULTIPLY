## 0. ゴール

- 2人対戦のターン制カードゲームを、静的サイトとして GitHub Pages に公開する
- 対戦形式：**ホットシート（同一端末で2人交互）** と **CPU対戦** の2モード
- すべて公開情報のゲームなので、秘匿画面や手札の裏面表示は不要
- バランス調整のため、**UIを介さずに大量自己対戦できるCLIシミュレータ**を同梱する

## 1. 設計方針（ここが最重要）

### 1-1. コアはUIから完全に分離した純関数にする

`src/core/` 配下は **DOM・React・ブラウザAPIに一切依存しない**。状態遷移は次の形に統一する。

```ts
applyMove(state: GameState, move: Move): GameState   // 非破壊。新しいstateを返す
legalMoves(state: GameState): Move[]                 // 対象選択まで含めて完全列挙
```

理由は3つ。

1. **CPUが先読みできる。** 探索は `applyMove` を繰り返すだけで実装できる
2. **バランス調整が高速に回る。** 同じコアをNode上で1万回叩ける
3. **テストが書ける。** 盤面を組んで合計数値を検証する単体テストが素直に書ける

state を破壊的に変更する実装にすると先読みが書けなくなるので、ここは妥協しないこと。immutable な更新を徹底する（構造が小さいのでコストは無視できる）。

### 1-2. 乱数はシード可能にして state に持たせる

`Math.random()` を直接呼ばない。PRNGの状態を `GameState` に含めることで、リプレイ・バグ再現・シミュレーションの再現性がすべて確保される。

```ts
// src/core/rng.ts
export type RngState = number;
export function nextRandom(s: RngState): [number, RngState] {
  let t = (s + 0x6D2B79F5) | 0;
  t = Math.imul(t ^ (t >>> 15), t | 1);
  t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
  return [((t ^ (t >>> 14)) >>> 0) / 4294967296, t];
}
```

### 1-3. ゾーンの表示名は差し替え可能にする

**ゾーン呼称は未定。** 内部識別子は `p0z0 / p0z1 / p1z0 / p1z1` に固定し、表示名は1ファイルに集約する。効果テキスト側もゾーン固有名を使わない設計になっているため、後から名前を決めても修正は表示層だけで済む。

```ts
// src/labels.ts
export const ZONE_LABELS = { z0: '第一', z1: '第二' } as const;  // ← ここだけ差し替える
```

### 1-4. CPUに山札の中身を見せない

山札の順序は非公開情報。CPUに `state` をそのまま渡すと**カンニングできてしまう**ので、思考ルーチンには「山札の残りカードの集合（順序なし）」だけを渡すビューを用意する。

```ts
export function visibleTo(state: GameState, p: PlayerId): PublicView
```

手札は両者公開なので、隠れているのは山札の順序だけ。

## 2. 技術選定

| 項目 | 選定 | 理由 |
|---|---|---|
| ビルド | Vite | Pages への静的出力が最短。設定は `base` 1行 |

外部の状態管理ライブラリ・UIライブラリは入れない。`useState` で `GameState` を1つ持てば足りる。

## 4. データモデル

```ts
// src/core/types.ts
export type PlayerId = 0 | 1;
export type ZoneKey = 'p0z0' | 'p0z1' | 'p1z0' | 'p1z1';
export const ALL_ZONES: ZoneKey[] = ['p0z0', 'p0z1', 'p1z0', 'p1z1'];

export type CardId =
  | 'gekko' | 'soyoku' | 'heigen' | 'hanmo' | 'hyozan' | 'uzushio'
  | 'shippu' | 'shiso' | 'kagero' | 'dangai' | 'ashikase' | 'horaana';

export interface CardDef {
  id: CardId;
  name: string;       // '月光'
  reading: string;    // 'げっこう'
  baseValue: number;  // 洞穴は0、足枷は-2
  priority: 0 | 1 | 2 | 3;
  hasOnPlace: boolean;
  copies: number;
  text: string;       // 表示用テキスト
}

export interface CardInstance {
  uid: number;        // インスタンス固有。同名カードの区別に必須
  defId: CardId;
}

export interface ZoneState {
  cards: CardInstance[];          // 氷山による制限は「氷山がこのゾーンにあるか」で判定する
}

export interface GameState {
  zones: Record<ZoneKey, ZoneState>;
  hands: [CardInstance[], CardInstance[]];
  deck: CardInstance[];           // 先頭がトップ
  discard: CardInstance[];
  turn: number;                   // 1〜14
  current: PlayerId;
  forcedZone: ZoneKey | null;     // 繁茂。構造上つねに0個か1個
  rng: RngState;
  log: LogEntry[];
  phase: 'playing' | 'finished';
}

export interface Move {
  cardUid: number;
  zone: ZoneKey;
  targetUid?: number;   // 渦潮・刺創の対象
  moveTo?: ZoneKey;     // 渦潮の移動先
  discardOnly?: boolean; // 安全弁（合法手0件時）
}
```

**`uid` は必須。** 同名カードが最大4枚あるため、カード名だけでは対象を一意に指定できない。

## 5. 数値計算エンジン（★最重要・最初に作る）

`優先度` は **数字が大きいものから先に処理**。先の層で確定した値は後の層で上書きしない。

```ts
// src/core/value.ts
export function cardValues(state: GameState, key: ZoneKey): Map<number, number> {
  const zone = state.zones[key];
  const has = (id: CardId) => zone.cards.some(c => c.defId === id);
  const out = new Map<number, number>();

  // 層1（優先度3）陽炎：すべての数値変動を無効化 → 本来の数値をそのまま返す
  if (has('kagero')) {
    for (const c of zone.cards) out.set(c.uid, base(c));
    return out;
  }

  // 層2（優先度2）洞穴：合計値を上書きするため個別値は意味を持たない
  //   → zoneTotal 側で早期returnする。ここでは本来の数値を入れておく
  if (has('horaana')) {
    for (const c of zone.cards) out.set(c.uid, base(c));
    return out;
  }

  // 層3（優先度1）月光：本来の数値が1なら3、それ以外は0。値はここで確定
  if (has('gekko')) {
    for (const c of zone.cards) out.set(c.uid, base(c) === 1 ? 3 : 0);
    return out;   // 確定済みなので層4は処理しない
  }

  // 層4（優先度0）個別の自己条件
  const n = zone.cards.length;
  const paired = soyokuPaired(state, ownerOf(key));
  for (const c of zone.cards) {
    let v = base(c);
    if (c.defId === 'soyoku'   && paired) v = 3;
    if (c.defId === 'dangai'   && n >= 3) v = 0;
    if (c.defId === 'ashikase' && n >= 5) v = 0;
    out.set(c.uid, v);
  }
  return out;
}

export function zoneTotal(state: GameState, key: ZoneKey): number {
  const zone = state.zones[key];
  const has = (id: CardId) => zone.cards.some(c => c.defId === id);
  if (!has('kagero') && has('horaana')) return 5;   // 層2。陽炎がなければ合計5固定
  return [...cardValues(state, key).values()].reduce((a, b) => a + b, 0);
}

// 双翼の成立判定：持ち主の2ゾーン両方に双翼が「存在するか」。
// 陽炎は数値変動を止めるだけで存在を隠さないので、陽炎のあるゾーンの双翼も数える。
function soyokuPaired(state: GameState, owner: PlayerId): boolean {
  return (['z0', 'z1'] as const).every(z =>
    state.zones[`p${owner}${z}` as ZoneKey].cards.some(c => c.defId === 'soyoku'));
}

export function score(state: GameState, p: PlayerId): number {
  return zoneTotal(state, `p${p}z0` as ZoneKey) * zoneTotal(state, `p${p}z1` as ZoneKey);
}
```

**再計算はキャッシュしない。** 盤面が変わるたびに全層を再計算する。カードは最大14枚なので性能上の問題は起きない。差分更新は不整合の温床になるので禁止。

## 6. ゾーンの設置制限（氷山）

氷山の効果は「**このゾーンには、本来の数値が2のカードしか置くことができない**」。
判定に必要なのは「このゾーンに氷山があるか」だけなので、枚数を数える状態は持たない。

```ts
// src/core/zone.ts
export const HYOZAN_ALLOWED_VALUE = 2;

export function onEnter(zone: ZoneState, card: CardInstance): ZoneState {
  return { cards: [...zone.cards, card] };
}

export function onLeave(zone: ZoneState, card: CardInstance): ZoneState {
  return { cards: zone.cards.filter(c => c.uid !== card.uid) };
}

export function isRestricted(zone: ZoneState): boolean {
  return zone.cards.some(c => c.defId === 'hyozan');
}

export function canPlace(zone: ZoneState, card: CardInstance): boolean {
  return !isRestricted(zone) || base(card) === HYOZAN_ALLOWED_VALUE;
}
```

- **判定は本来の数値**（正典 §2）。効果で変動した後の値は見ない
- 通せるのは氷山・渦潮・疾風（各3枚）。**氷山自身も2なので重ねられる**。枚数の上限はない
- 氷山が離れれば制限も消える。別の氷山が残っていれば維持される
- **「制限中のゾーンには必ず氷山がある」が保証される。** 氷山は3枚なので最大3ゾーン、何でも置けるゾーンが必ず1つ以上残る
- §1-1 に従い純関数にする（サンプルの破壊的シグネチャは採用しない）

## 7. ターン進行

```
1. phase !== 'playing' なら終了
2. 山札トップを1枚引いて current の手札に加える
3. forcedZone を capturedForce に退避し、forcedZone = null にする   ← ★
4. legalMoves(state) を列挙（capturedForce があり、かつそのゾーンにそのカードを置けるなら設置先を限定）
5. 手を選択（人間 = UI操作 / CPU = search）
6. カードをゾーンに設置（onEnter）
7. 設置時効果を解決（繁茂ならここで forcedZone が新たにセットされる）
8. turn++、current を交代
9. turn > 14 なら phase = 'finished'、得点計算
```

**ステップ3を必ず先に行う。** 先に `forcedZone` をクリアしないと、そのターンに繁茂を置いた場合に自分でセットした制約を自分で消してしまう。

### 設置時効果の実装

| カード | 処理 |
|---|---|
| 平原 | 手札全部を山札に戻す → シャッフル（rngを更新）→ 2枚引く |
| 繁茂 | `forcedZone = 設置したゾーン` |
| 渦潮 | `targetUid` のカードを `moveTo` へ（onLeave → onEnter）。設置時効果は再発動しない |
| 疾風 | `hands[0]` と `hands[1]` を交換 |
| 刺創 | `targetUid` のカードを `discard` へ（onLeave） |

氷山・陽炎・月光・双翼・断崖・足枷・洞穴は常在効果なので、設置時に特別な処理は不要（`zoneTotal` が毎回計算する）。

## 8. 合法手の列挙

```ts
export function legalMoves(state: GameState, force: ZoneKey | null): Move[] {
  const hand = state.hands[state.current];

  const moves: Move[] = [];
  for (const card of hand) {
    // 氷山の制限はカードごとに効くので、候補は手札1枚ずつ出す
    const open = ALL_ZONES.filter(z => canPlace(state.zones[z], card));
    // 繁茂の強制。ただし強制先にそのカードを置けなければ不発 → 自由に置ける
    const zones = (force && canPlace(state.zones[force], card)) ? [force] : open;

    for (const zone of zones) {
      const others = state.zones[zone].cards;   // 設置前の状態。自身は含まれない
      if (defOf(card).id === 'shiso') {
        if (others.length === 0) moves.push({ cardUid: card.uid, zone });   // 不発
        else for (const t of others) moves.push({ cardUid: card.uid, zone, targetUid: t.uid });
      } else if (defOf(card).id === 'uzushio') {
        // 移動先の可否は「移動するカード」で決まる
        let any = false;
        for (const t of others) for (const d of ALL_ZONES) {
          if (d === zone || !canPlace(state.zones[d], t)) continue;
          moves.push({ cardUid: card.uid, zone, targetUid: t.uid, moveTo: d });
          any = true;
        }
        if (!any) moves.push({ cardUid: card.uid, zone });   // 不発
      } else {
        moves.push({ cardUid: card.uid, zone });
      }
    }
  }

  // 安全弁：合法手が0件なら手札を1枚捨ててターン終了
  if (moves.length === 0) return hand.map(c => ({ cardUid: c.uid, zone: 'p0z0' as ZoneKey, discardOnly: true }));
  return moves;
}
```

- **渦潮・刺創は自身を対象に選べない。** 設置前のゾーン内容を対象候補にすれば自然に除外される
- 渦潮の移動先は元ゾーンと、**移動するカードを置けないゾーン**を除く
- 対象がいない場合は不発（カードは数値として残る）
- 安全弁はルール上到達しないが、カード追加時やバグ時にゲームがフリーズしないための最終防衛ライン。**CPU側も合法手0件の分岐を必ず持たせる**

## 10. CPU

```ts
export type Difficulty = 'easy' | 'normal' | 'hard';
export function chooseMove(view: PublicView, d: Difficulty): Move;
```

| 難易度 | 方式 |
|---|---|
| easy | 合法手からランダム |
| normal | 1手先読み。自分の手を適用した直後の評価値が最大の手 |
| hard | 2手先読み（自分の手 → 相手の最善応手）のミニマックス |

分岐数は概算で「手札2〜3枚 × 開いているゾーン最大4 × 対象組合せ」＝**多くて数十手**。2手先読みでも数千ノードなので、探索はブラウザ上で瞬時に終わる。

### 評価関数

```ts
export function evaluate(state: GameState, me: PlayerId): number {
  const opp = (1 - me) as PlayerId;
  let v = score(state, me) - score(state, opp);

  if (state.phase !== 'finished') {
    // 得点が積になるため、片方のゾーンが0だと総得点が0になる。終盤ほど強く警戒する
    const w = state.turn / 14;
    for (const z of ['z0', 'z1'] as const) {
      if (zoneTotal(state, `p${me}z${z.slice(1)}` as ZoneKey) <= 0) v -= 20 * w;
    }
    // 積は均衡させたほうが大きい（6×6=36 > 10×2=20）
    const a = zoneTotal(state, `p${me}z0`), b = zoneTotal(state, `p${me}z1`);
    v -= Math.abs(a - b) * 0.5;
  }
  return v;
}
```

相手の山札トップは不明なため、`hard` では相手の応手を読む際にドローを無視するか、残り山札から数枚サンプリングして平均を取る。まずは**ドロー無視**で実装し、弱ければサンプリングに拡張する。

## 11. バランス調整用シミュレータ

```
npm run sim -- --games 10000 --p0 hard --p1 hard --seed 42
```

コアが純関数なのでUIを介さず回せる。出力する指標と目標値。

| 指標 | 目標 | 何を見るか |
|---|---|---|
| 先攻勝率 | 50 ± 3% | 先攻後攻の有利不利。差があれば初期手札枚数などで補正 |
| 引き分け率 | 5% 未満 | 積が一致する頻度 |
| 0点決着率 | 5% 未満 | 片方のゾーンが0で終わる「事故」の頻度 |
| 平均スコア | 25〜35 | 設計上の想定は29 |
| **最終ターン逆転率** | 30% 未満 | **最重要。** 高いと「最後に置いた方が勝つ」ゲームになっている |
| カード別勝率貢献 | 極端な偏りがないこと | 使用したゲームの勝率。月光・洞穴・陽炎を重点監視 |
| カード別の設置先分布 | — | 自ゾーン／相手ゾーンの比率。相手ゾーンに一度も置かれないカードは妨害札として機能していない |

**最終ターン逆転率が高い場合の対処は既に検討済み**（月光・洞穴を設置時1回のみの効果に変更する案）。まずは現行ルールで計測し、数値を見て判断する。

## 14. 引き継ぎ時の注意（間違えやすい順）

1. **`forcedZone` のクリアは手の選択より前**。でないと繁茂を置いたターンに自分の制約を自分で消す
2. **層の処理順は優先度の降順**（陽炎3 → 洞穴2 → 月光1 → 自己条件0）。**先に確定した値は後の層で上書きしない**
3. **月光は「本来の数値」を見る**。効果で変動した後の値ではない
4. **陽炎は味方の強化も止める**（双翼の1→3も無効）。バグではなく仕様
5. **氷山がゾーンを離れたら制限解除**。「制限中のゾーンには必ず氷山がある」が詰み防止の要
6. **渦潮・刺創は自身を対象に取れない**。設置前のゾーン内容を候補にすれば自然に除外される
7. **渦潮で移動したカードの設置時効果は再発動しない**
8. **相手ゾーンに置いたカードは相手の得点になる**。効果文の「相手」は使用者から見た相手、数値の集計は持ち主基準
9. **CPUに山札の順序を渡さない**
10. **`Math.random()` を直接呼ばない**
